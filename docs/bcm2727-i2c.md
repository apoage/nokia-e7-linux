# BCM2727 I2C masters — full register/protocol decode + model/driver contract

**Date:** 2026-08-28 (task 111)
**Sources:** static disassembly of `firmware-re/analysis/nloader.bin` (Thumb,
base 0x10020000) and the Symbian ROM dump `firmware-re/dumps/romdumpplus.dmp`
(ARM, VA = 0x80000000 + file offset); anchors and dual-address-view background
from `docs/bcm2727-xti-trace.md` §2/§3; ICU conventions from
`docs/bcm2727-icu-timer.md` §2; device table cross-checked against
`docs/hardware-lore.md` §10.
**Confidence legend:** CONFIRMED = decoded from code on both sides (NLoader +
Symbian ROM driver) unless noted; INFERRED = interpretation of one side;
CONTRACT = semantics we choose for the QEMU model / Linux driver until
hardware says otherwise; OPEN = undecoded, do not guess.

---

## 0. Executive summary

1. The sys block carries **three identical I2C master engines** at
   **+0x2200 / +0x2300 / +0x2500** (phys 0x20202200/2300/2500, kernel VA
   0xC60322xx/23xx/25xx, pre-MMU/secure alias 0x200322xx/23xx/25xx —
   the "dual view" of xti-trace §3). CONFIRMED.
2. **Register map** (§2): status +0x08 (W1C), irq-enable +0x04, ctrl
   +0x24 (start/stop/direction/enable bits), length +0x18, data +0x1C
   (byte), clock divisor +0x28 (=504 both sides!), slave address +0x2C
   (7-bit), SCL timing pair +0x34/+0x38. CONFIRMED from NLoader's polled
   boot driver and the Symbian IRQ-driven I2C0 driver independently —
   the two sides agree on every shared field.
3. **Event bits** (status +0x08 = enable +0x04, same bitmap):
   bit0 Arbit(ration lost), bit1 Nack (NLoader's per-byte "error"
   poll — it is checking for NACK), bit2 Ardy (transaction done —
   the Symbian driver's name), bit3 RxData, bit4 TxData; bit12 =
   busy gate (NLoader only). CONFIRMED (bit names pinned by each
   ROM handler's trace string + the exact bit it clears:
   Arbit=0x801CD724 clears 1, Nack=0x801CD768 clears 2).
4. **IRQ:** one ICU id per bus — **I2C0 = ICU 0x96 (150)**, CONFIRMED
   (the ROM driver's ISR and every DFC tail write 0x96 to the ICU
   command port [0xC6060010] / EOI [0xC606000C], the same idiom as the
   tick timer's 0xF2). I2C1/I2C2 have **no Symbian user** — their ids
   are model-chosen (CONTRACT, §6).
5. **Bus citizens** (§5): bus 0 = PMIC "PEARL" TPS65950-class
   (0x48-0x4B), touch/compass/accel/NFC/ALS per hardware-lore §10;
   bus 2 = the charger pair probed by NLoader at 8-bit 0xD6/0xD4
   (7-bit 0x6B/0x6A): BQ2415x / SMB338 / SMB138. Bus 1 = no confirmed
   citizen (its DMA request lines exist — 0x13/0x14).
6. The QEMU chain boot drives the engines for real since task 112:
   the legacy globals+0x24 XTI shim (nokia_e7.c, which parked NLoader's
   channel at XTI RAM 0x401F0000) is **retired**; NLoader's selector —
   via the 0x200322xx alias view — initializes bus 2 through the
   `bcm2727.i2c` model and "init IC2_2 controller done" prints through
   the real engine (§6.1, implemented + chain-validated 2026-08-30;
   NLoader's own charger *probe* path is dead in the chain — §1.1
   correction — so the readreg traffic is exercised by the model's
   probe zone instead).  The Linux side is live since task 113:
   `i2c-bcm2727` registers three adapters, and `i2cdetect` sees
   exactly the modeled citizens (§6.2 as-built, validated 2026-08-30).

## 1. Who drives these engines (code map)

### 1.1 NLoader (boot-loader side, polled) — CONFIRMED

| VA | function |
|---|---|
| 0x100220D6 | channel select/init: arg 0/1/2 → base 0x20032200/2300/2500 into globals 0x100076F0+0x24; programs sys routing regs (§1.3); engine init sequence (§3.1); prints "init IC2_%d controller done" |
| 0x10022300 | `send(arg, buf, len)` — polled TX (§3.2) |
| 0x100223C4 | `recv(arg, buf, len)` — polled RX (§3.2) |
| 0x1002226A/82/9A/0x10022080 | ctrl-bit helpers: `|=2`, `|=3`, `|=3<<9`, `&=~(3<<9)` |
| 0x100222B4 | per-transfer setup: `[+0x2C] = (arg>>1)&0x3FF`, ctrl bit8 = arg bits[9:8] |
| 0x100222EE | busy gate: `[+0x08]` bit12 set → return "busy" (send/recv refuse) |
| 0x1002209A | clock helper: ctrl bit7 ← arg bit15..8 field, `[+0x28] = arg & 0x3FF` (called with 504) |
| 0x100224E8 | `readreg(arg, reg)` = send(arg, &reg, 1) then recv(arg, &b, 1) — classic write-index/read-back |
| 0x1002251A | charger probe + init (§4) |
| 0x100225F6 | wrapper: select channel 2 → probe, retry once (call sites 0x10020966/0x10020978 — see the correction below: never reached in the chain boot) |
| 0x1002238A | RX-phase ctrl shim: `ctrl |= 1<<10; delay; ctrl &= ~(1<<9)` |
| 0x100227EE/0x100227EC | empty lock/unlock stubs (`bx lr`) — the RMW "critical sections" are no-ops |

**Call-site decode correction (task 112, empirical):** the two probe
call sites sit inside 0x10020902 — a charger API whose prologue runs
the charger-state check 0x10022660 first — and that function **never
executes in the QEMU chain boot** (gdb breakpoint + zero I2C writes
after init; no BL, literal word, or pointer byte for 0x10020902/3
exists anywhere in the image — it is reached through a runtime-built,
SWBL-side dispatch we do not reconstruct). Gates decoded on the path:
`[globals+9] != 0` = "probe already done" → skip (under our flat load
that byte is a stale code value 0x98, hence a one-byte SWBL-role .bss
fixup in nokia_e7.c); the wrapper treats select()==0 as failure; and
the selector itself **short-circuits** — globals+0x24 already holding
the target base returns 1 without re-running the init sequence (why
the chain logs exactly one "init IC2_2 controller done": it comes
from the select-only call site 0x10022C14 in the GENIO/early path,
not from the probe wrapper).

All polling is padded with a delay loop `[0x30003E80] × N` (the boot
calibration factor; N = 200 per byte, 500 after init writes).

## 2. Register map (engine base + offset)

Widths: Symbian uses halfword access on everything except +0x1C
(byte); NLoader uses word access throughout — implement as 32-bit
registers, low half/low byte significant. Every field below is
CONFIRMED on both sides unless marked.

| offset | r/w | function | notes / status |
|---|---|---|---|
| +0x00 | R | capability/revision halfword | read once by Symbian ctor, saved to driver+0x134; never read by NLoader. Addr CONFIRMED, content OPEN |
| +0x04 | RW | **IRQ enable mask** (halfword) | bit0 Arbit, bit1 Nack, bit2 Ardy, bit3 RxData, bit4 TxData. Patterns: TX 0x13, RX 0xB, last-byte 0x07 (await Ardy). CONFIRMED |
| +0x08 | RW | **IRQ status** | read; **write-1-to-clear** (NLoader acks single bits 2/8/0x10; Symbian writes back the read value, or 0xFFFF to clear all before a transfer). bit12 = busy/locked (NLoader send/recv gate). CONFIRMED |
| +0x10 | R | init/ready status | bit0 polled ≤10000 times at NLoader init ("controller done" when set); Symbian never touches it. Behavior CONFIRMED, bit meaning INFERRED (ready flag) |
| +0x18 | W | **transfer length** (bytes) | written before every transfer, both sides. CONFIRMED |
| +0x1C | RW | **data byte** | write = TX byte, read = RX byte. CONFIRMED |
| +0x20 | W | mode/config | NLoader init writes 2; Symbian never writes. Observed, meaning OPEN |
| +0x24 | RW | **control** | bit0 START, bit1 STOP (auto-stop after length), bit7 clock enable (NLoader), bit8 read-phase flag (Symbian adds on reads), **bit9 TX direction** (set on every write config, cleared on every read config — both sides), bit10 data-phase enable (set in every transfer config), bit15 master enable. CONFIRMED as a bitmap; individual names INFERRED from use |
| +0x28 | W | **clock divisor** | **0x1F8 (504) written by BOTH sides** — the one magic constant they share. CONFIRMED |
| +0x2C | W | **slave address** (7-bit) | NLoader: `(arg>>1)&0x3FF` (e.g. 0xD6→0x6B); Symbian Configure: `[req+8]`. CONFIRMED |
| +0x30 | W | config halfword | NLoader init 2; Symbian init 0. Observed, meaning OPEN |
| +0x34 | W | **SCL timing A** = rate·K − 7 | Symbian per-speed-class (§1.2); NLoader init constant 0x39. CONFIRMED pattern |
| +0x38 | W | **SCL timing B** = rate·K2 − 5 | Symbian; NLoader init constant 0x3B. CONFIRMED pattern |

Speed-class constants (Symbian 0x801CE124, multiplier = derived
peripheral clock): case 2 → K=0xA8C(2700)/K2=0x8FC(2300); case 0 →
0x1A2C(6699)/0x1964(6500); case 1 → 0x1388(5000)/0x640(1600); both
with the −7/−5 offsets. The rate source is the clock-rate register
0xC6032644 (bits [20:16] × 38400, LSB field &0x1F+1) — same
environment as the icu-timer fast-counter code.

Not observed anywhere: +0x0C, +0x14, +0x3C+. Treat as absent.

## 3. Transfer sequences

### 3.1 NLoader engine init (per channel select) — CONFIRMED

```
[+0x20] = 2                       ; mode
delay(500×calib)
[+0x30] = 2 ; [+0x34] = 0x39 ; [+0x38] = 0x3B
clock(504):  ctrl |= 0x80 ; [+0x28] = 504
ctrl |= (1<<15)                   ; master enable
delay(10×calib)
ctrl &= ~(3<<9)                   ; idle direction bits
poll [+0x10] bit0 ≤ 10000 times   ; "ready"
printf("init IC2_%d controller done")   ← observed live in the QEMU chain log
```

Poll decode follow-up (task 112, from the selector tail at
0x10022248): the counter runs 10000 → 0 and **both** exits — bit0
observed set, or counter exhausted — fall through to the same "done"
print and return 1; only the (unreachable-in-practice) race of bit0
arriving exactly at counter == 0 skips the print.  Resolves the §7
"quirk or misdecode" item: quirk, as decoded — timeout also prints
done.  (The model sets bit0 after the first +0x20 write, so the poll
exits immediately.)

### 3.2 NLoader polled transfer — CONFIRMED

```
send(arg, buf, len):                 recv(arg, buf, len):
  if [+0x08] & (1<<12): return busy    if [+0x08] & (1<<12): return busy
  [+0x2C] = arg>>1                     [+0x2C] = arg>>1
  ctrl bit8 = (arg>>8)&3               ctrl bit8 = (arg>>8)&3
  [+0x18] = len                        [+0x18] = len
  ctrl |= 3<<9   (TX bits)             ctrl |= 1<<10; ctrl &= ~(1<<9)  (RX)
  ctrl |= 3      (START+STOP)          ctrl |= 3
  check [+0x08] bit1 → error path      check bit1 → error path
  per byte:                            per byte:
    poll [+0x08] bit4 (TX ready)         poll [+0x08] bit3 (RX avail)
    [+0x1C] = byte                       byte = [+0x1C]
    [+0x08] = 0x10   (ack)               [+0x08] = 8     (ack)
    delay(200×calib)                     delay(200×calib)
    check bit1                           check bit1
  ctrl &= ~(3<<9); return 0           ctrl &= ~(3<<9); return 0

error path (either): [+0x08] = 2 (ack) ; ctrl |= 2 (force STOP) ;
                     ctrl &= ~(3<<9) ; return 2
```

Note: the error bit1 trigger and the "busy" bit12 clear conditions are
not observed on hardware (no slave was modeled); NLoader tolerates
both.

### 3.3 Symbian IRQ-driven sequence — CONFIRMED

```
Configure (per request):  ctrl = 0 ; arm OperationTimer ; ctrl = 0x8000
                          [+0x2C] = [req+8] (slave addr)
                          [+0x34]/[+0x38] = speed-class timing
start (write):            [+0x18] = len ; [+0x08] = 0xFFFF (clear all)
                          [+0x04] = 0x13 (Nack|Arbit|TxData)
                          ctrl = 0x8601 | (0x100 if read phase) [| 2]
start (read):             same, enable = 0xB (Nack|Arbit|RxData),
                          ctrl = 0x8403 [+0x100 if read]

ISR (ICU 0x96):           cmd-port write 0x96
                          status = [+0x08] ; enable = [+0x04]
                          for each bit in (status & enable):
                              clear that bit in [+0x04]   (mask source)
                              queue its TInterruptDfc
                          if none fired: write status back (W1C all), EOI 0x96

TxData DFC:               [+0x08] = 0x10 (clear) ; [+0x1C] = next byte
                          [+0x04] = 0x13 (more) / 0x07 (last byte sent)
RxData DFC:               byte = [+0x1C] ; [+0x08] = 8 (clear)
                          [+0x04] = 0xB (more) / 0x07 (last)
Ardy DFC:                 [+0x08] = 4 ; [+0x08] = 4 (double write!)
                          complete (or next phase for combined req)
Arbit DFC:                [+0x08] = 1 ; complete (error 6)
Nack DFC:                 [+0x08] = 2 ; complete (error 0xA)
OperationTimer expiry:    status = [+0x08]; [+0x08] = status (clear all)
                          ctrl = 0 ; complete (timeout)
Complete:                 cmd-port 0x96 ; hand next queued request to DFC
```

Cross-check that the two sides describe the same engine: NLoader's
"poll bit4 → write byte" is Symbian's TxData IRQ; "poll bit3 → read
byte" is RxData; NLoader's per-byte bit1 error poll is the NACK
check (the ROM's Nack handler clears exactly bit1); NLoader ignores
Ardy (STOP completes blind), Symbian waits for it (enable 0x07 on the
last byte) — the model must set Ardy at transaction end.

## 4. Bus 2 decode: the charger command layer (NLoader) — CONFIRMED

Slave **0xD6** (7-bit 0x6B), channel 2:

- `id = readreg(0xD6, 3)`; classification of the id byte:
  - `id>>5 ∈ {2,4}` → **BQ2415x** family: prints (via an adr that
    lands 2 bytes into the string — runtime text is "2415%d found,
    rev:%x, (I2C_2)") with variant = ((id&3)==1 ? 0 : (id&3)+1),
    rev = id&7; then pushes a 1-2-entry init table (pointer
    0x10023DB6) of 2-byte (reg,value) writes.
  - `id>>5 == 0` and bit3 set → **SMB338**, letter = '@'+(id&3),
    rev = id&7; 9-10-entry init table (pointer 0x10023DBA).
  - `id>>5 == 0` and bit3 clear → **SMB138**, letter = 'A'+(id&3);
    same table.
  - else (or readreg returned 0 → "Read register (%02X) error.
    return 0x%X") → no charger.
  - All prints say **(I2C_2)** — the bus-2 assignment is CONFIRMED.
- **Init-table anomaly (OPEN):** both table pointers resolve into a
  printf-padding format string in the flat image ("    %d    %d   …",
  file offset 0x3DB6 — identical in both OneNAND copies). The write
  *mechanism* (byte pairs → 2-byte writes to 0xD6) is CONFIRMED; the
  table contents must be populated at runtime on hardware (region is
  used as scratch by the clock-print code) — treat contents as OPEN.
- Slave **0xD4** (7-bit 0x6A), also channel 2: polled alongside 0xD6 —
  `readreg(0xD4,1) & 2` vs `readreg(0xD6,1) & 2`; neither set prints
  "Hi-Z mode in DYN or USB charging IC". The pair matches the
  BQ24150/1 (0x6A) vs BQ24152+ (0x6B) address split.
- Charger state (0x10022660): `readreg(0xD6,0) & 0x30 == 0x10` →
  returns 0x10 (supply state); reg0 bit7 is another status return
  (0x10022638). Two 2-byte writes from RAM buffers 0x10007054 /
  0x10007056 (pool labels "Tp"/"Vp" — temperature/voltage parameter
  pushes).

This is the entire "companion-chip 0xD6 command channel" from
xti-trace §2 — it is a battery-charger conversation, nothing else.

## 6. Contract for the QEMU model + Linux driver (follow-up task)

Modeled on memcard doc §6.2. These semantics are ours until hardware
says otherwise. **Status: §6.1 is IMPLEMENTED and chain-validated
(task 112, 2026-08-30) — as-built notes at the end of §6.1; the
globals+0x24 XTI shim is retired (nokia_e7.c keeps a one-byte
SWBL-role .bss fixup for the probe-done flag, §1.1 correction). §6.2
is IMPLEMENTED and i2cdetect-validated (task 113, 2026-08-30) — as-built
notes at the end of §6.2.** Scope of the two tasks:
`emulation/qemu/hw/arm/bcm2727.c`
"bcm2727.i2c" model + `drivers/i2c/busses/i2c-bcm2727.c` + DTS nodes.

### 6.1 QEMU model

- **Three engines** at sys+0x2200/2300/2500, 0x40 register file each,
  32-bit registers (accept word and halfword writes; +0x1C accepts
  byte). All of §2's offsets exist; unknown offsets read 0.
- **Transfer state machine** (event-driven, no clocking): a ctrl write
  with bit0 (START) and bit15 set latches address = +0x2C, direction =
  **ctrl bit9 (1=write, 0=read)**, length = +0x18, auto-stop = ctrl
  bit1. bit8 is accepted and ignored for direction purposes (both
  sides' read configs work under the bit9 rule).
- **TX**: each +0x1C write pushes a byte to the attached slave, sets
  status bit4 (TxData) and IRQ if enabled; when byte count reaches
  length: set bit2 (Ardy) — transaction complete (STOP if armed).
- **RX**: when armed, each +0x1C read pulls the next slave byte and
  sets bit3 (RxData); after length bytes set bit2.
- **Address NAK** (no device at +0x2C on START): set bit1 (Nack) +
  complete; never set bit0 (single master — Arbit stays 0).
- **Status**: W1C semantics (a write clears the bits set in the written
  value; 0xFFFF clears all). bit12 reflects "transaction open" (makes
  NLoader's busy gate meaningful). +0x10 bit0 always reads 1 after any
  +0x20 write (satisfies the init poll; the chain boot then prints
  "init IC2_2 controller done" through the real engine).
- **IRQ**: level-held while `(status & enable) != 0`; I2C0 raises ICU
  id **0x96** (CONFIRMED). I2C1/I2C2 raise model-chosen unused ids —
  **0x97/0x98 suggested** (0x97 has no ROM `mov r0,#imm` claimant;
  re-check the ICU model's claim list when wiring).
- **Devices** for i2cdetect to be meaningful (the whole point —
  i2c-tools are already in the rootfs, task 103):
  - bus 2: a charger responder at 0x6B implementing readreg semantics
    (write 1 byte = reg index, read bytes back) with reg3 = a BQ2415x
    id (`id>>5 == 2`), so NLoader's probe prints its "found" line and
    `i2cdetect -y 2` shows `6b`. Optionally 0x6A as well.
  - bus 0: minimal responders at 0x48-0x4B (PMIC: echo registers) so
    the Symbian-era addresses show up in `i2cdetect -y 0`.
  - all other addresses NAK → i2cdetect prints `--`.
  - `-drive`-backed or built-in stubs both fine; keep it in the spirit
    of the memcard model (env-gated `I2C_DEBUG` trace).
- **Timing/divisor registers** (+0x28, +0x34, +0x38, +0x30, +0x20,
  +0x00): plain RW storage (nothing in the model consumes them).

**As-built notes (task 112, 2026-08-30).**

- Location: `bcm2727.i2c` in `emulation/qemu/hw/arm/bcm2727.c` — one
  0x340 IO region at 0x20202200 (engine windows +0x000/+0x100/+0x300,
  0x40 each) plus the `bcm2727.i2c-secure` alias at 0x20032200.  No
  overlaps: the OneNAND window ends at 0x2002FFFF, memcard starts at
  0x20202800.  The three buses are real QEMU I2CBus (`i2c-0/1/2`);
  stubs are I2CSlave types `bcm2727.i2c-echo` (write-1-byte = register
  index, further bytes store, reads auto-increment — readreg
  semantics) and `bcm2727.i2c-charger` (same mechanics, power-on regs:
  reg0 = 0x10 supply state, reg3 = **0x49** → id>>5 == 2, (id&3) == 1
  → variant 0, rev 1 — i.e. the "24150 found, rev:1, (I2C_2)" line
  NLoader's classifier would print).  PMIC echoes 0x48-0x4B on bus 0,
  charger 0x6B on bus 2, everything else NAKs.  IRQs are level-held
  on `(status & enable)` into ICU **0x96/0x97/0x98** (0x96 CONFIRMED;
  0x97/0x98 checked unclaimed).  Env knob `I2C_DEBUG=1` traces
  register writes and bus traffic (`i2cN: W/TX/RX/START/NAK/Ardy`).
- **START latch refinement** (the contract text "bit0 + bit15 set"
  needed one): NLoader's send()/recv() epilogues leave bit0 SET, so
  any-write latching re-opens a spurious transaction at every "clear
  direction bits" write and wedges the next transfer on the bit12
  busy gate.  The implemented rule: the latch fires when the write
  ARMS the data phase — bit0 + bit15 + bit9/bit10 present — and that
  composite was not already armed, **or** bit9 (direction) changed
  while armed.  Both proven flows fit: NLoader's `|= 3<<9` / `|= 3` /
  `&= ~(3<<9)` sequences and Symbian's Configure (ctrl = 0) between
  phases.  (Drivers that keep bit0 set across a combined
  write-then-read must pass through an unarmed ctrl value or flip
  bit9 — Symbian's own shape already does.)
- **TxData/RxData are ready/avail events, not one-shots**: set at
  START, re-fired on their W1C ack while the transaction still wants
  bytes (the ack is the "byte consumed" edge — both drivers ack AFTER
  moving the byte; NLoader polls bit → moves byte → acks, so the
  re-arm on ack is what makes the next poll succeed).  An early
  version got this wrong and also chained the ctrl-arm mask as
  `v & bit0 & bit15` (always 0 — bitwise masks don't chain across
  different bits); the probe exerciser below caught both.
- **Probe exerciser zone @ 0x40221000** (`bcm2727.i2c-probe`,
  QEMU-only scaffolding in the gpio-sim zone family): write a 7-bit
  address and bus 2's engine runs one full readreg cycle
  (write-index 0x03, read-back 1) through the regular state machine
  and stubs, restoring engine state afterwards.  Exists because
  NLoader's own probe path never executes in the chain (§1.1
  correction) — with `I2C_DEBUG=1`, `devmem 0x40221000 32 0x6b` from
  the Linux shell prints the full exchange
  (`START TX addr=0x6b → TX 0x03 → Ardy → START RX → RX 0x49 → Ardy`)
  and `i2c-probe: readreg(0x6b, 3) = 0x49`; an absent address NAKs.
- **Validation**: shim retired, chain boots to `e7:~#` with the
  marker flow identical to `emulation/qemu-e7sw/boot-baseline-
  task104.log`; NLoader's §3.1 init sequence traced through the
  0x2003 alias (divisor 0x1F8); `devmem 0x20032528` reads 0x000001F8
  from Linux (the §Validation-3 sanity, guest-side); engine-0 +0x10
  reads 0 (never initialized — correct).  Log:
  `emulation/qemu-e7sw/boot-i2c-task112.log`.

### 6.2 Linux driver

- `drivers/i2c/busses/i2c-bcm2727.c`, three DTS nodes:
  `i2c@20202200`, `i2c@20202300`, `i2c@20202500` (each `reg = <… 0x40>`,
  `compatible = "broadcom,bcm2727-i2c"`). Use `devm_ioremap` (NOT
  `devm_ioremap_resource`) — the windows sit inside the GENIO pinctrl
  node's exclusive sys-page claim, same situation as the memcard
  channels (memcard doc §6.1 item 2).
- Interrupts: `interrupts = <150 …>` for bus 0 (ICU 0x96), the chosen
  ids for buses 1/2. Poll fallback when the IRQ resource is missing
  (mirrors the memcard driver's evolution).
- Transfer algorithm (start from the NLoader polled shape — it is the
  simpler of the two proven flows):
  1. `[+0x2C] = msg->addr` (7-bit, i2c-core supplies it that way);
  2. `[+0x18] = msg->len`;
  3. ctrl = `0x8603` for write / `0x8503`-style for read (Symbian's
     constants — bit0+bit1+bit15 + bit9 (tx) or bit8+bit10 (rx));
     combined write-then-read (an `I2C_M_RD` msg following a write in
     one xfer) = Symbian's read-phase pattern: run the write first
     WITHOUT stop (ctrl bit1 clear — the 0x8601 base), then the read
     with repeated start. The model treats each START as its own
     transaction segment; it must not require a STOP between segments.
  4. per byte: wait status bit4 (write) / bit3 (read) — IRQ-driven with
     the poll fallback — then +0x1C write / read, ack with a 0x10/0x08
     status write;
  5. wait bit2 (Ardy) for completion, check bit1 (Nack → `-ENXIO`) /
     bit0 (Arbit → `-EAGAIN`); ack everything.
- Init per probe: `[+0x28] = 504`, `[+0x34] = 0x39`, `[+0x38] = 0x3B`,
  `[+0x20] = 2`, `[+0x30] = 2` (NLoader's proven constants — exact
  SCL rate is irrelevant to the model; hardware bring-up can refine
  with Symbian's speed-class formula).
- **Validation plan** (the follow-up's exit criterion): chain boot
  still prints NLoader's "init IC2_2 controller done" through the real
  engine (shim removed); Linux boots with the three adapters
  registered; `i2cdetect -y 0/2` lists exactly the modeled addresses;
  an `i2cget`/`i2cset` round trip on the charger stub matches; eMMC
  root still mounts (the sys-page neighborhood is shared — watch for
  GENIO/memcard regressions).

**As-built notes (task 113, 2026-08-30).**

- Driver: `kernel/linux/drivers/i2c/busses/i2c-bcm2727.c` (built-in,
  `I2C_BCM2727`); three DTS nodes in the live
  `arch/arm/boot/dts/broadcom/bcm2727.dtsi` (`i2c@20202200/2300/2500`,
  `interrupts = <150/151/152>`, reg windows 0x40); defconfig gains
  `I2C=y`, `I2C_CHARDEV=y` (i2c-tools need /dev/i2c-N built in — no
  modules in the chain), `I2C_BCM2727=y`; mirror synced.  Adapter
  numbers are pinned to the engine index (numbered adapter), so
  i2c-0/i2c-2 are the firmware's I2C_0/I2C_2 regardless of probe order.
- One deliberate deviation from the contract text: `compatible` is
  `"brcm,bcm2727b1-i2c"` (the house convention every other node uses),
  not the literal `"broadcom,bcm2727-i2c"` §6.2 spelled.  Erratum,
  cosmetic only.
- Transfer shape as contracted: per-segment unarmed pass-through ctrl
  (`MASTER|CLKEN = 0x8080`) before the armed write (write `0x8603`,
  read `0x8503`, Symbian's constants) — required by the §6.1
  arm-edge START latch for back-to-back same-direction transfers;
  combined write-then-read arms no STOP on the write message (only
  the last message of the xfer sets bit1), and the model's
  repeated-start path closes each segment at its Ardy exactly as
  implemented.  Per byte: wait bit4/bit3 (IRQ wake with poll
  fallback), move via +0x1C, ack bit4/bit3 (the model re-fires on the
  ack); segment ends on Ardy; Nack → `-ENXIO` (i2cdetect prints
  `--`), Arbit → `-EAGAIN`.  Error epilogue = NLoader's (force STOP,
  clear direction bits).
- IRQ discipline (the level-held line + the Symbian ISR's +0x04
  trick): the ISR masks the fired event bits in the enable register
  and wakes the transfer loop; the loop re-arms `0x1f` after each
  byte move, and the level line re-asserts if the model re-fired the
  event — no lost wakes, no storm.  Poll mode (no IRQ resource) never
  writes a nonzero enable.
- **Validation** (log `emulation/qemu-e7sw/boot-i2c-task113.log`):
  three "bcm2727-i2c: adapter N ... IRQ-driven" probes, boot to
  `e7:~#` with the eMMC root mounted; `i2cdetect -y 0` lists exactly
  48 49 4a 4b, `i2cdetect -y 2` exactly 6b (6a absent — not modeled),
  all other cells `--`; `i2cget -y 2 0x6b 0x03` = 0x49 (the BQ2415x
  id), `i2cset 0x05 0x5a` → read-back 0x5a (the i2cget/i2cset pair
  exercises the combined write-read without STOP); boot diff vs the
  task-104 baseline = the three adapter lines + `i2c_dev:` init line
  + build strings only (the `softuart:` line is a pre-existing
  since-task-109 delta).  `/proc/interrupts`: ICU 150/151/152 claimed
  by the three adapters, zero idle counts before any i2c traffic (no
  early-IRQ storm — the optional su-console `-icount` spot check was
  skipped on that evidence), 112/0/128 after the detection sweeps.
  The old probe-exerciser zone (`devmem 0x40221000`) still works
  alongside — the driver and the exerciser drive the same engine
  state machine without interference.

  SWBL-side dispatch, not reconstructed — §1.1 correction).

## 8. Method / reproducibility

- NLoader: Thumb disassembly at base 0x10020000 (capstone); anchors
  from xti-trace §6. Literal-pool annotation + string dump; the
  charger tables were cross-checked against both OneNAND copies of
  NLoader (identical). BL-census by scanning BL/BLX pairs.
- ROM: literal-pool scan for 0xC60322xx/23xx/25xx words (LDR-literal
  xref census with ARM PC+8 base), then ARM disassembly of the xref
  cluster; handler identification by cleared status bit + trace
  string; ICU id from the command/EOI write pattern (validated
  against the tick-timer idiom, icu-timer §1).
- Scratch scripts in /tmp/i2cdis.py (thumb/arm disassembler helper
  with literal resolution — note the ARM/Thumb PC-offset difference).
